# Iranian SMS provider qualification inventory

Planning amendment 2026-10-31. Thirty discovery candidates are listed, including branded panels and enterprise platforms. This is not a national register, a count of independent APIs or a promise that all candidates ship. No provider is marked qualified by this documentation update.

Target: deliver as many providers as can actually be verified and tested, with remaining expansion at the end of the approved P1 tranche. Initial Kavenegar and second Melipayamak are defaults subject to qualification. Each row has its own specification -> implementation -> local qualification -> authorized live qualification chain; failures or missing accounts do not block other rows. Public sources above were collected during the side-conversation research on 31 October 2026. Some pages or technical guides were inaccessible and some references are historical. Specification must recheck current official contracts, supplier identity and account requirements. A research reference does not establish live availability, feature parity, prices, service quality or current interoperability. Rows remain unqualified, with exact API versions and real-account capabilities to be recorded during execution.

The CSV stores each candidate and stage ID. Update capability/evidence records for sending, templates, delivery receipts, inbound messages, sender lines, balance/quotas, callback verification, credential handling, failures and FA/DE/EN workflows. A provider without a verified capability must show that limitation explicitly. Protect current UI, common CONN/EVT ownership and existing permission/offboarding controls.
