# Security reports

Use [GitHub private vulnerability reporting](https://github.com/KhademOHAli1/warpdrive/security/advisories/new) for suspected vulnerabilities. Private reporting is enabled for this public repository. Include the affected version or commit, the affected component, steps to reproduce, impact and sanitized evidence. For a self-hosted instance, identify the installed component revision if it differs from the repository or release tag. Do not open a public issue containing exploit details, customer records, mail, tokens or installed-system logs.

The repository maintainer, @KhademOHAli1, coordinates triage, remediation and disclosure. A report is not a promise of a response deadline or support for an untested version. Security fixes follow the same revision-specific integration, acceptance and release gates as other changes; disclosure and production deployment are separate decisions.

If the private-report form is unavailable, open a public issue asking for a private contact, without vulnerability details. Never paste credentials into an issue, release note or build artifact.
