## Original current-shell flow proposal

These controls and state behaviors are design hypotheses informed by existing source and the inspected references. They require candidate implementation and review.

| Flow                    | Entry and controls                                                                                                                                                                                                                         | Persistence and recovery                                                                                                                                                                                                |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Create pipeline         | Existing picker or company-pipelines action opens current Dialog. Name first, then existing visibility-group selection and concise access explanation. Keep a fast blank path. Later template/duplicate choices retain their own previews. | Create pipeline and stages together. Disable duplicate submission while saving; retain draft and focus on validation/denial. On success open the requested board/editor. Closing returns focus to the invoking control. |
| Manage and share        | Extend existing SettingsCard and edit surface. Separate stages, access and lifecycle sections. Show scope plus effective capability/record limits; avoid a generic promise of full access.                                                 | Explicit save. Denied or stale saves keep the draft and show persistent inline feedback. Re-read a changed policy before retrying. Permission changes require server enforcement and audit evidence.                    |
| Archive and restore     | Pipeline management offers separate active/archived lists. Show consequences, dependencies and record preservation before archive. Use precise pipeline wording instead of the toolbar's deal Archive label.                               | Archive is reversible, not purge. Restore keeps IDs/history and rechecks effective access. Recovery must offer a permitted navigation destination.                                                                      |
| Save a view             | Reuse current filter/view controls. Show personal/shared ownership and explain that sharing the view does not share records. Preserve raw names.                                                                                           | Keep filter AST and entity compatibility. Saving/deletion refreshes relevant caches; failure retains the user's conditions. A shared view still queries only permitted records.                                         |
| Install a template      | Existing shell and shared Dialog/Sheet contain blank/template choice, preview, version, stages/fields/views, access and inactive effects.                                                                                                  | Explicit install distinct from activation. No historical messages, automatic permission broadening or mass moves. Upgrade diff and conflict recovery remain separate work.                                              |
| Blocked stage move      | Current board/record interaction shows actionable missing requirements and permitted resolution actions. Use a non-drag alternative.                                                                                                       | Failed movement keeps the deal at its saved stage and retains form edits. Do not expose hidden evidence. Override appears only when permitted and auditable.                                                            |
| Future workspace switch | Explicit company security context and account identity, distinct from pipeline picker. Available only after SP-14 qualification.                                                                                                           | Handle unsaved work; verify membership, clear scoped caches/subscriptions and reauthorize deep links. A visible dropdown alone is not isolation.                                                                        |

No new reusable interactive primitive is required by the initial proposal. If an adapter lacks an API, document the exact gap before extending it. Do not create a second shell, authentication authority, workflow engine or mail sender.
