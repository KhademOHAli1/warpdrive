# Reviewer intake interface

The privacy settings root now offers a separate reviewer intake card after the existing personal-request form. Requester case-detail pages remain requester-bound and do not mount this queue. The UI uses the existing settings surfaces, buttons, locale direction and date/time formatters. Farsi, German and English copy is complete; UUID references remain LTR inside RTL text.

The initial card does not fetch requests. An explicit load first rechecks the current native security status, then invokes the existing reviewer Server Action. Neither administrator status nor a client reviewer UUID supplies authority. The UUID only rejects a stale form. The server requires current `case.assign` for the minimal intake view; initial assignment also requires `authority.manage` and `case.review` in the existing transaction service.

The live view displays only the opaque case reference, type, status, received instant and response due instant. Each request is bounded to 25 rows. Load-more uses the exact returned cursor and deduplicates repeated IDs to the latest returned version. It does not establish a stable snapshot, complete subject scope or permission to read case contents. No reviewer link reuses the own-request detail route.

Taking a case freezes its case ID, current version and one command ID. An unclear response retains that intent; explicit retry uses the same command after another security check. No mutation is automatically resent. A recorded receipt is historical and does not assert current ownership, disclosure approval, data changes or case completion. Refreshing obtains a new live view rather than deriving current state from the receipt.

Account changes, sign-out, MFA/enrollment requirements and unavailable security status hide cached reviewer data and suppress late results. Current access/freshness denial also clears a previously recorded receipt. The same-account uncertain command remains available for safe reconciliation after access is restored. Personal-form state is separate; shared security-check supersession cannot authorize a retry from a stale result.

All reviewer content is inside the existing replay-block/no-capture boundary. This is a source declaration, not installed telemetry acceptance. Intents live in component memory, not a durable browser store. Closing or reloading the page does not establish a remote rollback or a verified memory erase. Existing database idempotency and version checks remain the mutation authority.

## Evidence and open work

The corrected first UI run observed ten missing-interface assertion failures; five root-mount controls passed after four earlier intended mount failures. The first 15 cases then passed. Independent review found cached assignment receipts surviving permission/fresh-auth denial; two new regressions failed before the minimal receipt-clearing fix, with three passing controls for pagination, same-account interruption and MFA changes.

After refactoring and explicit inventory registration, the final selection passed 69 tests in ten files: 20 new UI/mount cases, 20 existing personal-workspace regressions and 29 registry cases. Execution used one worker and no database, browser or provider service. The locale audit passed with no catalog issues or new raw-copy findings. The final configured Next type-generation/full type-check pipeline and 12-file typed ESLint passed on the corrected private source. The first compiler pass exposed three lint errors and one warning; callback declarations, dependency capture and synchronous state updates in an effect were corrected without suppressions. Protected cached state now adjusts in a guarded render before commit, and the layout effect cancels in-flight work. The 69 cases passed again after this refactor. A second allocation was returned unstarted because another workspace had an active compiler. The third one-use allocation completed successfully in 14.738 seconds, with actual process-group absence observed within 24.068 seconds of launch. It ran in warning mode with 46 percent available memory sampled and up to 1,764,992 KiB sampled aggregate RSS; the peak between samples was unmeasured.

These component/action-boundary results do not establish native authentication, HTTP behavior, database authorization, visual/device acceptance or a completed reviewer workspace. Durable disclosure-scope sealing, reviewed source/projection content, export jobs/repair and full reviewer case decisions remain unfinished. The full DPL-01 through DPL-36 goal and all 12 installed/operator gates remain open; no staging deployment exists yet.
