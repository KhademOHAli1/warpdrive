## Suggested implementation order

1. **Consent and shared chrome:** OAuth consent, release banner, shared label/edit accessibility copy, navigation fallback titles. These are bounded, independent surfaces with explicit semantics and little dependency on provider behavior.
2. **Shared import stepper and collaboration input/display:** render-time step labels/numbers, presence overflow/a11y, supported Persian/Arabic digit shortcuts. Preserve guards and internal identifiers; qualify the Persian keyboard layout in Chrome.
3. **Enrichment dialog:** feature catalog, canonical-key display resolver, errors/outcome/age/clock helpers, field selection/overwrite controls. Keep backend/provider protocol semantics stable.
4. **Prospect workflow:** filters and provider selection, search/results, reveal, review/apply/resume, then explicit safe localized backend-error mapping. Cover computed/camelCase labels and locale changes during an active workflow.
5. **Closeout review:** regenerate the inventory after peer implementations settle; review the remaining findings by disposition rather than widening the baseline. Run focused Farsi/English regression checks and browser workflows in the implementing tranche. Separately qualify mixed-direction names/URLs, long Persian labels, Persian keyboard input, and assistive labels. This audit itself supplies source evidence only.

No audit exceptions or baseline waivers are requested by this document. Invariants should be kept only with a specific reviewed reason; genuine user-facing English and raw backend prose remain open work.
