Compatibility is material:

- [decode-uri-component 0.5.1](https://raw.githubusercontent.com/SamVerschueren/decode-uri-component/v0.5.1/index.js) is ESM with a default function. Installed query-string 7 expects `require(...)` to return a callable directly. Overriding only its version does not prove compatibility.
- [query-string 10's manifest](https://raw.githubusercontent.com/sindresorhus/query-string/v10.0.0/package.json) removes this decoder dependency, uses ESM, and declares Node 22+. Its [entrypoint](https://raw.githubusercontent.com/sindresorhus/query-string/v10.0.0/index.js) exports the API as default; MinIO's existing namespace imports expect named stringify. A version override alone can break actual storage operations.
- [stream-json's vendor history](https://raw.githubusercontent.com/uhop/stream-json/master/README.md) describes a functional API rewrite in 2.x, ESM in 3.x and later JSONL delegation. MinIO imports `stream-json/jsonl/Parser.js` with a class/static `make` interface. Replacing the package with 3.8 is not a drop-in change.
- The [minimatch 11 changelog](https://raw.githubusercontent.com/isaacs/minimatch/v11.0.3/changelog.md) removes RegExp-based APIs and changes matching semantics. The [glob 14 changelog](https://raw.githubusercontent.com/isaacs/node-glob/v14.0.3/changelog.md) adapts to that matcher, changes some patterns/ignore behavior and fixes cancellation. Test file selection, not just imports.
- Current parent registry releases remain [MinIO 8.0.7](https://registry.npmjs.org/minio), [Drizzle Kit 0.31.11](https://registry.npmjs.org/drizzle-kit), [shadcn 4.23.0](https://registry.npmjs.org/shadcn), [registry helper 0.2.1](https://registry.npmjs.org/%40shadcn%2Fregistry) and [Testcontainers 12.2.1](https://registry.npmjs.org/testcontainers). A blanket parent update presently offers no established fix. ESLint 10.14.0 still requests minimatch 10, so that parent update alone also does not settle this advisory.

Registry license metadata for candidate versions: decoder 0.5.1, query-string 10, esbuild 0.28.2 and deepmerge 4.3.1 declare MIT; stream-json 3.8 declares BSD-3-Clause; **glob 14.0.3 and minimatch 11.0.3 declare BlueOak-1.0.0**, so do not carry forward historical license labels. Record licenses/notices for the actual final lock graph. Query-string 10 declares Node 22+; glob/minimatch declare Node 18, 20 or 22+. These metadata declarations do not substitute for Bun runtime qualification.

## 4. Recommended bounded remediation order

**Root owns package/lock/patch edits and any implementation.** These are concrete candidates for qualification, not changes already made or compatibility guarantees.

1. **Runtime dependency boundary first:** prefer an override to query-string 10.0.0 plus a small, recorded MinIO 8.0.7 Bun patch adapting query-string imports in both CJS and ESM client/helper files to the default API. This removes the vulnerable decoder package without rewriting its algorithm. Prove that the exact serialization/signing contract is retained before accepting it. If that fails, backport the linear 0.5.1 decoding algorithm into the old CJS package with license attribution and bounded malformed-input regressions. A backport retains the version-based audit finding and needs explicit patch evidence; it is not a clean audit.
2. **Keep stream-json disposition explicit:** no uncalled package-wide finding is silently ignored. Record the narrow JSONL/native-parser assessment and owner/review trigger. If policy requires removing the old major before release, qualify a separately scoped MinIO notification compatibility patch to the current parser API, or backport the affected 1.x Assembler/filter operations. Neither is a safe version-only override. Do not enable additional stream-json features meanwhile.
3. **Remove old esbuild server-capable code:** qualify a scoped legacy esbuild override to 0.25.12 with Drizzle config loading and migration rehearsal. The deprecated esbuild-kit parent is not repaired merely by updating the direct esbuild dependency.
4. **Fix dev tooling without changing UI:** deepmerge needs a reviewed patch guarding dangerous keys before writes from both target and source, including null-prototype targets; see the [upstream report and proposed fix](https://github.com/TehShrike/deepmerge/issues/273). Apply to resolved CJS/ESM distribution entrypoints, not only unused source. Preserve symbols, arrays and valid custom merge semantics. Review untrusted registries before running an overwrite workflow.
5. **Upgrade the archive/matching pair deliberately:** test glob 14.0.3 + minimatch 11.0.3 with Testcontainers/archiver, then qualify the remaining minimatch consumers under 11 separately. If the old parent APIs cannot support it, use targeted backports rather than a global force override. Archiver 8 is another candidate but is ESM and outside Testcontainers' current ^7 range; do not label it a patch update.

Do not replace MinIO with another S3 SDK merely to obtain a lower audit count; that is a larger storage/API/credential review. Do not suppress advisory IDs, relabel package versions or treat absent HTTP exploit evidence as a security fix.
