# Privacy archive storage boundary

This is an internal, injected-configuration S3 adapter under development. It has no production factory, environment activation, public route, presigned URL, case authority, durable job or publication grant. DPL-09/10/17 remain open. The existing CRM file storage client and running preview are unchanged.

## Attempt and object identities

`createExportObjectStore(config)` validates a fixed endpoint, bucket, credentials and finite request timeout. Configuration is server/operator input; it must not come from an export HTTP request. Operational results expose static failure codes. Driver payloads, credentials, bearer URLs and raw headers are absent.

`allocate()` creates opaque artifact and attempt UUIDs before remote I/O. The future job must durably record the attempt before `begin(attempt, {maxBytes}, signal)`. The adapter reconstructs only `privacy-exports/v1/<artifact>/<attempt>.tar.gz`; callers cannot submit an arbitrary key or filename. A lost initiation response can leave an upload requiring exact-attempt inspection; it is not a clean failure receipt.

`begin` checks that bucket versioning is already Enabled and never provisions or changes the bucket. It returns the exact upload ID and a writable sink. The sink uploads serial fixed parts of at most 5 MiB with backpressure and a byte quota. Finishing bytes leaves an incomplete upload; `complete(codecReceipt, signal)` is a separate effect. Completion compares independently measured bytes/SHA-256 with the codec receipt, then requires an exact-version HEAD. An ETag is not a SHA-256 checksum.

The original attempt's cancellation remains relevant through completion. The archive codec and S3 sink are independent contracts: the storage adapter does not parse a TAR archive, approve source content or prove the codec receipt's authority. Only the future server job may connect current approved sources, codec success and artifact publication.

## Reads, cleanup and uncertain effects

`open`, `stat` and `remove` require the generated attempt identity and exact nonempty object version. Reads stream; they do not buffer the whole object. New HTTP/TLS operations receive a real AbortSignal and a finite deadline. The SDK's automatic retries and tracing remain disabled.

`inspect(attempt)` lists only the exact generated key, with explicit bounded/truncation outcomes. It is a repair primitive, not approval to disclose or delete everything returned. Multiple versions/uploads are distinct residuals. Exact object-version removal verifies absence and preserves other versions. It does not bypass governance retention, legal holds or object locks.

`abort(uploadRef)` targets only that multipart upload and verifies upload absence. `upload_absent_verified` does not mean there is no completed object: a raced or previously accepted completion must be inspected and handled separately. A lost completion/deletion response, a denied delete or an incomplete inspection must remain uncertain/blocked until authoritative reconciliation. The future job needs durable repair obligations; an in-memory callback cannot supply them.
