## Screens and contract

- `/projects` keeps the Client screen and links to the internal list when the module is enabled. `/projects/internal` lists projects visible to the active staff member and offers creation when admitted. `/projects/internal/[projectId]` contains the work-item List and Board and owner-managed membership.
- `ProjectIndex` carries visible project summaries and a create capability. `ProjectWorkspace` carries the project, one ordered item set, member and assignee summaries and action capabilities. Eligible staff options for membership management are owner-only.
- Typed commands create projects or items by stable intent ID, update items by project, item and revision, and set or remove a member by project and user. Core checks scope and grants again for every mutation. Membership revocation clears matching assignments in the same transaction. Assignment remains a project-local operation.
- Follow the existing [Web reads](../../src/frontend/reads.ts) and [registered command bridge](../../src/server/actions/registry.ts). The explicit fixture adapter exercises the same command interface before Core wiring. Production reads and mutations use Core only.
- The additive canonical migration backfills existing project identity as Client and preserves IDs, CRM references, memberships, receipts and audit history. Legacy reads and commands remain Client-scoped, so baseline Web can run on retained upgraded Core.
