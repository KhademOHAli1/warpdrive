# Scope decisions, sources and assumptions

31 October 2026. Evidence is one prospective agency's account of its workflow, with transcription/translation uncertainty. This is product direction, not validated market demand, measured savings or competitor research.

## Direct user decisions

1. Keep customers in their preferred communication channels. Prioritize internal coordination and reminders.
2. Freelancer coordination is in scope as a specialized CRM/project workflow and optional module.
3. Feedback/revisions are in scope as integrated project coordination.
4. Invoice preparation is a later stage, excluded from this implementation goal.
5. Final asset storage/delivery is outside scope.
6. Project economics are in scope with quotation/cost dependencies and bounded claims.
7. Preserve the current UI and existing system investments. Farsi first, German second, English supported.
8. The latest user instruction explicitly requests an extensive coordinated plan, then implementation in a new chat with a new goal. It authorizes routine local implementation after the plan; no extra blanket approval loop is needed.

The uncertain competitor name in the voice transcription is not resolved or used as a verified requirement. No feature-parity or demand claim is inferred from podcast advertisements.

## Design assumptions and validation

| Assumption | Validation and owner |
| --- | --- |
| An internally managed freelancer workflow is useful without external accounts. | Agency implementation walks through modeling/video scenarios, then seeks actual permitted agency feedback. |
| Update commitments help even without WhatsApp synchronization. | Test a staff-recorded channel workflow and measure missed commitments in a later authorized pilot. |
| Three starter templates cover enough initial work. | Model modeling, short video and campaign scenarios; edit templates rather than expanding into a general resource-planning suite. |
| Existing activities can safely serve project coordination. | Calendar/AP owners review complete visibility/state ownership and real deny/race tests before exposing bindings. |
| Shared WF/EVT/MAIL APIs will become available incrementally. | Use actual committed exports only; keep missing effects disabled and progress pure/internal work independently. |
| Financial reporting can consume quotation/cost evidence. | IG-12/13 and Agency owners accept the source/version/permission/money contract; no provisional data is called actual profit. |
| Native-language review will be available. | Record actual reviewer feedback separately from static catalogs and automated render/browser tests; do not invent participants. |

## Metrics and claims

Release targets are testable: zero unauthorized project/financial disclosure in the defined surface matrix, no duplicate intended records/effects under the specified retry races, complete new FA/DE/EN state coverage and preserved exact regional values. These are acceptance targets, not current outcomes.

Business metrics need an actual baseline: missed update commitments, producer coordination time, revision turnaround and time from approved milestone to billing handoff. Capture baseline on a few authorized real projects before setting numeric improvement promises. No fixed staffing, cost, calendar delivery date or measured productivity gain is invented here.
