## Concrete driver and proposed operation

The actual driver is node-postgres `pg`. `Db` is the base `NodePgDatabase<typeof schema>` from `src/db/client.ts`, usable by both the production handle and actual `makeTestDb()` fixture. The real transaction callback type is extracted as already done by native source, rather than substituting a root Db for a transaction. The public `TransactionRollbackError`/`tx.rollback()` behavior is used by `nativeAuthGateway`; error-valued Result alone does not roll back a transaction.

Revised feature-local API: `runAuthorityTransactionCandidate(pool, spec, signal, operation)` returns Promise<Result<T, E | authority_transaction_unavailable | authority_commit_outcome_unknown>>. It is a review candidate, not the absent accepted Platform/shared authority API. `operation` receives the actual transaction and required AbortSignal and returns an actual Result. No project permission, identity, scope or Privacy admission is inferred.

`parseAuthorityTransactionSpec(unknown)` validates native candidate configuration exactly once: strict required key tuple of two signed int32 values, fixed shared/exclusive mode and lock/statement/idle timeout milliseconds. Each timeout is an integer1..60000 and lock<=statement<=idle. Valid syntax reserves no production key or budgets. Tests use explicit synthetic keys only. No default key, string-hash namespace, browser authority DTO or production key assignment is introduced.

Capture a detached key tuple, mode and every SQL timeout before the first await, so caller mutation during pool acquisition cannot switch lock identity or combine timeout versions. The planned outer transaction requests READ COMMITTED, configures transaction-local SQL timeouts using constant setting names, then obtains one transaction-level `pg_advisory_xact_lock_shared` or `pg_advisory_xact_lock` with the supplied key. Authority/business reads are separate statements after that awaited lock. No helper lock upgrade or nested transaction is introduced. The revised API type takes pg.Pool. Its planned implementation must check the actual public Pool runtime class before any query, lease its own client and construct drizzle(client,{schema}) internally. The current rejection scaffold performs no SQL or checkout and qualifies none of those behaviors. Arbitrary Db, client-backed wrappers and PgTransaction/savepoint arguments are rejected before SQL. An actual already-open REPEATABLE READ wrapper with uncommitted sentinel must remain untouched on rejection. A Pool lease excludes a simultaneous valid borrower; it does not prove that every external pool caller returned an idle clean client. Platform is reviewing whether a private dedicated pool factory is required before any shared-fence acceptance.

An error Result is captured outside the callback and invokes `tx.rollback()`. The rollback exception is handled only outside the outer transaction. An unexpected database error after an OK callback has entered COMMIT must retain an unknown-commit outcome, not become evidence of an unsaved operation. AbortError must propagate; tested pre-commit cancellation is distinct from the unqualified COMMIT-cancellation case.
