# Published-version comparison

Version history keeps its existing primary publication selection and restore-as-draft action. After selecting a publication, a separate comparison selector can show structural changes from another publication to the primary selection. Clearing comparison returns to the same read-only graph. Comparison does not save, publish, restore, run a workflow or change the restoration target.

The view compares workflow names, steps matched by stable graph identity, step settings/naming/action versions, connections matched by source/port/target and diagram positions. Node-array, edge-array and object-key order do not create changes. Array order inside settings remains meaningful. Reconnected or rebranched connections appear as removed plus added; retained duplicate connections keep their multiplicity. Layout changes are reported separately from steps and connections.

The comparison helper returns a whitelist of authorized names, finite change flags and ports, counts and generated numeric presentation ordinals. Stored settings, their keys/literals/references, full nodes and raw graph IDs are not returned or rendered in the comparison. The existing individual-version graph can still inspect its separately authorized configuration. Comparison adds no live entity or connection-label lookup.

Both existing exact-version queries retain current server-side viewer authorization. Dialog-local query options force fresh reads without changing global cache policy. The comparison is hidden during fetching, errors, placeholders or mismatched selected numbers/summary IDs. A workflow identity switch resets both selections. Read retries remain separate from restoration and make no write. Current-as-of-read authorization is not a global fence against later permission changes; server authentication and expected-revision checks remain authoritative for restoration.

Retained data is checked locally before it can be called unchanged. Missing/unsupported graph schemas, unknown root/node/edge fields, duplicate/missing step IDs, dangling connections and malformed positions produce a generic unavailable state. Graph bounds stay at 100 nodes and 200 edges; layout admits up to 100 valid identifier/finite-coordinate entries within ±100,000, including detached entries allowed by the canonical schema. A shared ceiling of 100,000 JSON traversal/comparison entries bounds local work. Settings remain opaque JSON under this limit; no new server validator or execution contract is introduced.

The final local focused run passed 86 cases across three files: 20 dialog cases, 40 helper cases and all 26 existing lifecycle cases. A deferred-retry regression first reproduced a ready new pair being blocked by an old request; retry state now follows the selection generation. Formatting and the locale audit passed. Hosted checks, native UI and human accessibility remain separate gates.

The frozen baseline exercised the actual former dialog: its two existing preview/close controls passed, ten cases failed at the missing comparison control, and a separate workflow-switch case exposed retained selection. The regression suite preserves those assertions and adds same-version, clear/change selection, partial retry, error-redaction and helper admission/ordering cases. Exact qualification belongs to the selected PR revision and its retained evidence; these tests do not establish native UI, human accessibility or full workflow acceptance.

This is a published-version increment toward WF026 and UX-11. Draft-to-publication impact review, unpublished-draft simulation, complete #683 acceptance, included-main qualification, release, deployment and provider/installation acceptance remain open. Closing the dialog or hiding a denied view does not erase authorized definitions from browser caches or implement a retention policy.
