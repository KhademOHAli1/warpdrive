# Private governed input writer

`src/features/stats/governedInputRepository.ts` expects the [unnumbered SQL custody proposal](governed-source-storage-proposal.sql). The prepared native fixture applies it only to its disposable database. These files supply no migration number, database role, credential, provider or application entry point.

The planner and writer share `canonicalAnalyticsInputEvent`. The writer persists those exact UTF-8 bytes, retains the original payload spellings, and verifies the same bytes as well as the fingerprint.

The trusted server adapter must own the nominal `AuthenticatedGovernedInput` proof type and its private brand. Bind it to the one exact validated batch, current server authentication, registered producer and principal, and applicable source, consent, CRM link and assignment policy. The authentication reference is an opaque audit reference. Store no credentials and accept no caller-created proof. The fixture uses a synthetic type assertion solely to exercise database custody. Interactive sessions also require a current active user row. That row cannot establish session freshness or source permission.

Supply an exclusive writer pool with bounded checkout, known idle connections, fixed text decoding, and a trusted search path. One read-committed write transaction locks the producer and matching grants, validates complete bounded receipt chains, and writes the immutable header, events and lines. A second bounded read-only transaction verifies the committed receipt. A missing confirmation returns the internal admission ID and `commit-unconfirmed`. An exact replay under fresh authority may add a new delivery receipt while preserving event uniqueness and the first receipt. Recovery must not assume a rollback from cancellation, a lost connection, or an unconfirmed receipt.

Deployment still needs separate trusted writer and authority-administration privileges. PostgreSQL row-locking SELECTs require UPDATE privilege on a column of each locked table. Qualify narrow controlled lock helpers or appropriately scoped privileges before deployment, especially for the active-user lookup. The writer must not gain ordinary user, producer or grant mutation authority through role configuration. Registry administration should follow the same producer-first lock order. The private fixture runs under a disposable database owner and supplies no installed privilege or real-source qualification.
