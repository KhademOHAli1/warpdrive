# Private pre-target forecast commit observation

The reader checks the private forecast snapshot table and returns internal evidence. Disposable custody fixtures cover rejection before commit, confirmation after commit, a different or inactive creator, a one-microsecond target mismatch, an incorrect digest, a dirty session and a privileged tuple replacement. Hosted native qualification is pending.

Use a dedicated trusted pool connected to the same primary and installation as the writer. Require finite checkout and transport query timeouts. The helper rejects sessions whose PostgreSQL ReadyForQuery status is already in a transaction or failed. It opens a fresh read-only repeatable-read transaction and samples database wall time in its first data statement, after the active MVCC snapshot exists. The stored row must already be visible and its top-level XID must be visible in that native witness. The physical tuple's raw `xmin` must match the native XID conversion of the persisted `xid8` stamp. Qualify only forecast inserts executed in the top-level writer transaction. Savepoint inserts can carry a subtransaction tuple XID and are denied by this baseline. The original capture witness must exclude the writer's own XID. [PostgreSQL snapshot functions](https://www.postgresql.org/docs/16/functions-info.html#FUNCTIONS-PG-SNAPSHOT), [repeatable-read semantics](https://www.postgresql.org/docs/16/transaction-iso.html#XACT-REPEATABLE-READ), [tuple system columns](https://www.postgresql.org/docs/16/ddl-system-columns.html), [database clocks](https://www.postgresql.org/docs/16/functions-datetime.html#FUNCTIONS-DATETIME-CURRENT).

Pass the authenticated creator from the server session and the exact insert receipt plus original expected hashes. Check request identity, activation, original currency, capture witness, prediction cutoff, insert time, both target bounds and calendar/zone. The active user row is verified in the same snapshot. The SQL recomputes both digests within the existing byte limits and never returns the raw request, result, assumptions or roster. A distinct or deactivated creator and receipt mismatches all return an unavailable result. Current report and roster access, session freshness and installed custody integrity remain the owning adapter's separate checks.

The accepted sampled time is an upper bound on committed visibility in the trusted primary's wall-clock domain. It is at or after insertion and strictly before target start at native microsecond precision. This is not a transaction commit timestamp, a durable proof writer or a way to qualify an older forecast after target start. The caller must preserve the authenticated observation immutably, reverify receipt and evaluation scope, and pass its confirmed time to the saved forecast evaluator. Proof persistence, access grants, reader routing and clock operational qualification remain open.
