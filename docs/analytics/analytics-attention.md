# Current deal next actions

The Activities queue SQL has an internal report mode for the scope, projection, observation metadata and cap. Existing queue callers keep their request shape, temporal selection, authorization, payload and paging behavior.

The reader accepts an authenticated server actor and explicit currency, pipeline and owner selection. It rehydrates current authority in an owned repeatable-read transaction and preserves the original actor's authority ceiling. Named pipeline and owner availability, row visibility, exact in-scope counts and the sorted requested page come from the same data statement. Scope predicates apply to the linked deal before count and pagination. Owner selection means the deal owner, regardless of the activity assignee. Deal-less work is outside this report. The report represents current work independent of the dashboard's historical date range.

The shared queue SQL retains its two rules. A missing next step is an open deal with no unfinished, undeleted linked activity. An undated unfinished linked activity satisfies that rule. Overdue work retains the queue's dominant-parent authorization and includes unfinished qualifying activity linked to a still-live closed deal. Timed work must precede the sampled database clock. All-day work becomes overdue after its final civil day in the account timezone, using the queue's canonical-date or legacy placeholder rule. The private report uses PostgreSQL's timezone data for the sampled instant and legacy placeholders. Its exact evidence carries either a UTC microsecond due instant or a final civil day with its basis.

Counts refer to overdue activities and deals missing a step. They are not a distinct-deal total. When there are more than 5,000 authorized matches, the reader withholds the bounded result rather than presenting a partial count. Zero matches, a later empty page, missing scope, permission, source failure and match cap remain distinguishable. Only the source's authorized deal/activity anchors and rule evidence leave the repository. Record reads and mutations still require their normal current authorization.

Each page has its own observation and read ID. Complete means the single page contains every match from its own statement. Independent page reads cannot be combined into a snapshot export. The fixture definitions cover same-scope count/paging, due-time equality and civil days, revoked or unavailable scope, native clock shape and cap rejection. Native qualification, advanced rules and scoped records navigation remain open.

The Pipeline tab publishes separate authorized counts and the account time zone used by the queue. The route omits all anchors and row evidence. The existing historical date range has no effect on these counts.
