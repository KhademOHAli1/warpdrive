# Private native forecast outcome collection

This private collector for #600 and #602 produces bounded native outcome evidence under current authority. Immutable actual custody and model qualification are separate steps.

The first compatible receipt is an explicitly selected original or correction, owned by the current authenticated actor, for a single pipeline and that actor's own deals. The saved scope is exactly `{ ownerId, pipelineId }`. The saved report definition must pin `outcomeDefinition: "first-net-observed-open-to-won-v1"` and `settlementPolicy: "post-target-native-barrier-v1"` in the original request bytes. The collector checks the original native commit proof against the immutable tuple identity, target, capture and confirmation witnesses, both byte digests and the open roster. It never follows a correction link implicitly. The nominal input still requires a trusted future issuer to establish original writer custody, exact forecast population completeness and the independent proof. The storage trigger checks submitted members and does not independently prove that the producer selected the whole authorized roster.

The actor and live deal membership are resolved in the collection snapshot. The current pipeline must be permitted and have a matching captured head with no reused identity. Every saved open member must still have its own captured, authorized live incarnation, owner, pipeline and currency. Every after-anchor raw state remains live and in that same scope. A missing row, transferred owner, hidden parent, replaced incarnation, scope change, archive interval, insufficient capture, budget exhaustion or broken chain withholds the entire collection. The source bounds the full stored roster to 1,000 rows, each selected history corpus to 5,000 events and 8 MiB, and native witnesses to 64 KiB.

## Settlement fence

The caller supplies a UTC-microsecond settlement fence at or after the target's exclusive end. On the same trusted primary as capture, the dedicated idle pool session first completes an autocommit statement that assigns a top-level XID at or after that fence. It then opens a fresh read-only repeatable-read transaction. The first data observation requires the barrier to be below snapshot xmax and visible, with no listed active XID at or below it. A source transaction with an in-period captured observation already held its top-level XID before this later barrier. The newer cut therefore includes its committed work or rejects the still-pending cut. Empty xip without a committed barrier is insufficient because transactions at or above xmax are also invisible. The barrier consumes an XID without modifying application rows. This policy needs a monotonic trusted primary wall-clock domain and uninterrupted capture. Unrelated older active XIDs can conservatively withhold collection, so this availability signal stays private. [PostgreSQL snapshot and XID functions](https://www.postgresql.org/docs/16/functions-info.html).

Classification uses the first in-period net open-to-won transition after folding each transaction. The last observation in the folded transaction defines event time. A multiwrite transaction straddling a target boundary is withheld. Imported won/lost dates and commit-time inference do not participate. For a first observed win, original currency and value come from the transaction-final captured state. The full settled chain can prove a no-win while distinguishing still open, closed lost, and a win observed before the period. A direct closed-to-closed outcome correction before period end is withheld pending a declared restatement source. Later edits do not replace the original first in-period value or create an in-period win.
