# Observed deal cohorts

The Pipeline report compares monthly groups of currently visible, unarchived deals at 30, 60 or 90 elapsed days. The period, pipeline, owner and currency filters select the current population. Entry is the recorded native deal insert, not the editable creation date or an activation baseline. A qualifying win is the first observed transaction-final open-to-won change. Deals that have not reached the selected age are separate from mature deals. If any mature outcome is unknown, the report shows known wins and counts and withholds the rate.

The server owns one read-only repeatable-read observation and applies the current request ceiling, current live deal access and current permission over every retained deal and pipeline side used by the calculation. This does not reconstruct earlier actor entitlements. A permission, bounds or integrity failure returns a generic unavailable state. PostgreSQL's [JSON record conversion](https://www.postgresql.org/docs/16/functions-json.html) gives the shared deal-visibility predicate native UUID and UUID-array inputs. The browser receives aggregate counts, the effective owner selection kind and covered bounds. It receives no deal, actor, event or snapshot identifiers and no protected diagnostic reason.

The table reports the calendar and time zone that defined the server result. The dashboard page, its drill-down and cohorts resolve display preferences from the same request cookies and account policy. A saved manual zone wins; browser mode may use the current device zone, without treating a client cache-key parameter as authority. Selected dates and capture availability can each clip a calendar month. A newly opened panel waits for a fresh permission-checked request before showing results. Capture not started, period outside capture and an unavailable report are separate states. Unavailable reads can be retried without displaying prior results.

Report periods use named time zones. Bare offsets are rejected at the preference boundary because [Intl UTC offsets](https://tc39.es/ecma402/#sec-createdatetimeformat) and [PostgreSQL POSIX zone specifications](https://www.postgresql.org/docs/16/datetime-posix-timezone-specs.html) can interpret an offset string differently. A valid named saved zone remains usable when a device cookie is invalid.

The prepared hosted browser journey first checks the no-capture state against the canonical prefix. After the existing dashboard journeys finish, the disposable runner applies the private proposal and adds one observed insert with an older business creation date. The panel must show one immature entry, exclude all activation baselines, keep the rate unavailable and switch horizons through the real protected request. This is a synthetic source qualification path. It does not install a canonical migration.

The unnumbered history proposal still needs canonical admission, native qualification and exact browser proof for this report. The cohort only covers observed deal inserts and authorized history. Acquisition cohorts, currently open outcome counts, time-series curves, saved reports and retained-deal policies remain separate scope.
